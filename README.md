# Обробка даних проєктних задач засобами Python

## Опис проєкту

У межах цієї роботи я розробила Python-пакет для обробки даних проєктних задач із CSV-файлу. Програма зчитує дані, перевіряє їхню коректність, виконує аналіз і формує текстовий звіт.

Мій варіант завдання — № 22. Предметна область — проєктні задачі.

## Структура проєкту

Під час розробки я розподілила програму на окремі модулі:

- `loader.py` — зчитування CSV-файлу, перевірка даних і перетворення кількості годин на числове значення.
- `analysis.py` — фільтрація задач, обчислення кількості годин і групування даних за відповідальними особами.
- `reporting.py` — формування текстового звіту.
- `cli.py` — запуск програми через командний рядок.
- `errors.py` — визначення власного винятку для помилок даних.

Також я створила каталог `tests/` з автоматизованими тестами, каталог `data/` із вхідними даними та каталог `reports/` для сформованого звіту.

## Вхідні дані

Я підготувала CSV-файл `data/tasks.csv` із такими полями:

| Поле | Призначення |
|---|---|
| `name` | Назва задачі |
| `assignee` | Відповідальна особа |
| `hours` | Кількість годин |
| `status` | Статус задачі |
| `priority` | Пріоритет задачі |

Під час зчитування даних я використала `csv.DictReader`, кодування UTF-8 і параметр `newline=""`. Текстові значення очищуються від зайвих пробілів, а статус і пріоритет переводяться в нижній регістр. Поле `hours` перевіряється та перетворюється відповідно до правил, реалізованих у програмі.

## Аналіз даних

У програмі я реалізувала такі операції:

- відбір задач, статус яких не дорівнює `done`;
- підрахунок кількості активних задач;
- обчислення загальної кількості годин;
- групування годин за відповідальними особами;
- визначення унікальних відповідальних осіб;
- відбір задач із високим пріоритетом.

Для обробки даних я використала списки, словники, множини та включення списків (list comprehensions).

Функція аналізу підтримує додаткові параметри фільтрації, зокрема мінімальну кількість годин, а також можливість врахування виконаних задач.

## Формування звіту

Я реалізувала формування текстового звіту у файлі `reports/report.txt`. Звіт містить кількість активних задач, загальну кількість годин, розподіл годин за відповідальними особами, список унікальних виконавців і перелік задач із високим пріоритетом.

Для запису результатів я використала `pathlib.Path`, контекстний менеджер `with` і кодування UTF-8. Програма також створює необхідні батьківські каталоги для вихідного файлу.

## Обробка помилок

Я додала перевірки вхідних даних. Програма повідомляє про відсутні обов’язкові стовпці, пропущені значення, некоректну кількість годин, від’ємні значення та помилки читання файлу.

Для помилок даних я створила власний клас `DataError`. У повідомленнях про некоректні дані зазначається відповідна інформація, зокрема номер рядка або назва поля, якщо це можливо визначити.

У CLI реалізовано обробку помилок читання та запису. У разі помилки програма повертає ненульовий код завершення, що дає змогу правильно перевіряти результат її роботи автоматизованими засобами.

## Запуск програми

Я налаштувала запуск програми через командний рядок із зазначенням вхідного CSV-файлу та шляху до вихідного звіту:

```bash
python -m project_tasks.cli data/tasks.csv reports/report.txt
```

Також у `pyproject.toml` я налаштувала команду `project-tasks` для запуску встановленого пакета.

## Тестування та перевірка якості коду

Я створила автоматизовані тести для перевірки завантаження даних, аналізу, формування звіту та роботи CLI.

Для запуску тестів я використала команду:

```bash
python -m pytest
```

Останній підтверджений результат локальної перевірки: **18 passed**.

Також я перевірила якість коду за допомогою Ruff. Перевірка стилю виконується командою:

```bash
python -m ruff check .
```

Перевірка форматування виконується командою:

```bash
python -m ruff format --check .
```

Останній підтверджений результат перевірки форматування: `12 files already formatted`.

## Збирання пакета

Я налаштувала параметри пакета у файлі `pyproject.toml` і вказала версію `6.0.0`.

Для збирання пакета я використала команду:


Збирання завершилося успішно. Було створено два дистрибутиви:

- `project_tasks-6.0.0.tar.gz`

Також я перевірила запуск CLI після встановлення пакета в окреме віртуальне середовище. Під час контрольного запуску програма сформувала звіт із 6 активними задачами та загальною кількістю 26 годин.

## Автоматизація перевірок

Я створила конфігурацію GitHub Actions у файлі `.github/workflows/python-ci.yml`.

У ній налаштовано матрицю перевірок для трьох операційних систем — Ubuntu, macOS і Windows — та трьох версій Python: 3.11, 3.12 і 3.13.

Автоматизація охоплює встановлення залежностей, запуск Ruff, перевірку форматування, виконання тестів, перевірку роботи CLI та збирання пакета. Результати перевірок у GitHub Actions були успішними: усі 9 завдань матриці CI завершилися без помилок.

## Академічна доброчесність

Під час виконання лабораторної роботи основним допоміжним інструментом на основі штучного інтелекту був **GitHub Copilot**, який використовувався під час розроблення та перевірки Python-проєкту. Він допомагав отримувати пропозиції щодо написання коду, розбиратися з помилками, покращувати структуру функцій і формувати ідеї для тестування. Також його підказки використовувалися як допоміжний засіб під час роботи з CSV-файлами, обробки винятків і перевірки коректності результатів.

Пропозиції GitHub Copilot не приймалися автоматично без перевірки. Код перевірявся шляхом запуску програми, виконання модульних тестів за допомогою `pytest`, статичного аналізу та перевірки форматування за допомогою `ruff`. Окремо перевірялися формування звіту, обробка помилок і код завершення CLI. Остаточні рішення щодо структури проєкту та внесення змін приймалися після аналізу результатів перевірок.

ChatGPT використовувався додатково для уточнення окремих технічних питань і структурування пояснень до звіту. Його роль була допоміжною: результати роботи перевірялися на відповідність реалізованому коду та фактичним результатам запуску.

Використання інструментів штучного інтелекту не замінювало самостійного розуміння виконаних дій. Відповідальність за перевірку коду, правильність результатів і зміст поданого звіту несе автор роботи. Усі наведені результати тестування та пакування мають відповідати фактично виконаним перевіркам.
