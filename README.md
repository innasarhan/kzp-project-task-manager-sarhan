
# Project Task Manager

## Опис проєкту

**Project Task Manager** — Java-проєкт для роботи з проєктними задачами: зберігання, пошуку, перевірки та обміну даними у форматі CSV.

- **Предметна область:** проєктні задачі
- **Варіант:** 22
- **Лабораторна робота:** №5
- **Java:** 21
- **Система збірки:** Maven
- **Версія:** 5.0.0

У лабораторній роботі №5 реалізовано узагальнений репозиторій `Repository<T>`, універсальний CSV-експорт та імпорт на основі Java Reflection і анотації `@CsvColumn`, а також обробку помилок формату та файлових операцій.

Попередню функціональність проєкту та наявні тести збережено для сумісності з попередніми лабораторними роботами.

## Мета лабораторної роботи

- Реалізувати узагальнений клас `Repository<T>`.
- Забезпечити додавання, отримання знімка та пошук елементів за `Predicate`.
- Створити анотацію `@CsvColumn` для позначення полів, що беруть участь у CSV-обміні.
- Реалізувати універсальний CSV-експорт через Reflection.
- Реалізувати імпорт CSV у типізовані Java-об'єкти.
- Забезпечити детермінований порядок стовпців.
- Реалізувати коректне екранування ком, подвійних лапок і перенесень рядків.
- Обробляти помилки формату CSV і файлові помилки.
- Зберігати початкову причину помилки у власному винятку.
- Перевірити роботу компонентів автоматичними тестами.
- Зберегти сумісність із попередніми лабораторними роботами.
- Перевірити збірку, статичний аналіз і CI.

## Структура даних лабораторної №5

Для CSV-функціональності використовується клас `ProjectTaskRecord`.

Він містить такі поля:

| Поле | Тип | Заголовок CSV |
|---|---|---|
| `name` | `String` | `назва` |
| `assignee` | `String` | `виконавець` |
| `estimatedHours` | `double` | `години` |
| `status` | `TaskStatus` | `статус` |
| `priority` | `TaskPriority` | `пріоритет` |

Поля, які потрібно включати до CSV, позначаються анотацією `@CsvColumn`.

Приклад:

```java
@CsvColumn("назва")
private String name;

@CsvColumn("виконавець")
private String assignee;
```

Значення анотації визначає назву відповідної колонки. Поля для CSV обробляються за детермінованим правилом: сортуються за назвами Java-полів.

## Перелічувані типи

### TaskStatus

Для представлення стану задачі використовується `TaskStatus`:

- `TODO`
- `IN_PROGRESS`
- `DONE`

### TaskPriority

Для представлення пріоритету задачі використовується `TaskPriority`:

- `LOW`
- `MEDIUM`
- `HIGH`

Під час імпорту значення перетворюються на відповідні константи Java. Невідоме значення enum розглядається як помилка формату CSV.

## Узагальнений репозиторій

Клас `Repository<T>` забезпечує типобезпечне зберігання об'єктів заданого типу.

Основні операції:

- `add(T item)` — додає елемент до репозиторію.
- `snapshot()` — повертає незмінний знімок поточного набору елементів.
- `search(Predicate<T> predicate)` — шукає елементи за заданою умовою.
- `size()` — повертає кількість елементів.
- `isEmpty()` — перевіряє, чи репозиторій порожній.

Приклад використання:

```java
Repository<ProjectTaskRecord> repository =
        new Repository<>();

repository.add(new ProjectTaskRecord(
        "Розробити API",
        "Іван",
        12.5,
        TaskStatus.IN_PROGRESS,
        TaskPriority.HIGH
));

var results = repository.search(
        task -> task.getPriority() == TaskPriority.HIGH
);
```

Параметр типу `T` дає змогу повторно використовувати репозиторій для різних типів об'єктів без прив'язки до конкретної предметної моделі.

Знімок репозиторію не дозволяє зовнішньому коду безпосередньо змінювати внутрішню колекцію через повернене представлення.

## CSV-анотація

`CsvColumn` — анотація, яка позначає поля для CSV-експорту та імпорту.

Анотація доступна під час виконання програми, щоб механізм Reflection міг отримувати її значення.

Значення анотації використовується як назва колонки CSV. Поля без `@CsvColumn` не включаються до CSV-схеми.

## CSV-експорт

Клас `CsvExporter` відповідає за універсальний експорт об'єктів у CSV-файл.

Основний метод:

```java
export(List<T> items, Path path)
```

Експортер використовує Reflection для отримання полів, позначених `@CsvColumn`, замість окремого жорстко заданого переліку полів для кожного класу.

Основні характеристики:

- формування заголовків на основі анотацій;
- детермінований порядок стовпців;
- отримання значень полів через Reflection;
- запис файлу за допомогою `Path` та `Files`;
- явне використання UTF-8;
- екранування ком, подвійних лапок і перенесень рядків;
- обробка порожнього набору записів.

Для порожнього набору створюється порожній CSV-файл без записів даних.

## CSV-імпорт

Клас `CsvImporter` читає CSV-файл, перевіряє його структуру та перетворює записи на об'єкти заданого типу.

Основний метод:

```java
importFile(Path path, Class<T> type)
```

Під час імпорту перевіряються заголовки, кількість полів і коректність значень. Текстові дані перетворюються на відповідні типи Java, зокрема числові значення та enum.

Парсер підтримує:

- поля, що містять коми;
- подвійні лапки всередині поля;
- перенесення рядків усередині лапок;
- перевірку кількості полів;
- перевірку числових значень;
- перевірку значень enum;
- обробку порожнього файлу.

Для відновлення об'єктів використовується Reflection відповідно до реалізованого контракту CSV-моделі.

## CSV-формат

Для нової функціональності лабораторної №5 використовується CSV із комою як роздільником.

Приклад заголовка:

```csv
виконавець,години,назва,пріоритет,статус
```

Приклад даних:

```csv
виконавець,години,назва,пріоритет,статус
Іван,12.5,Розробити API,HIGH,IN_PROGRESS
Олена,8.0,Створити дизайн,MEDIUM,TODO
Андрій,5.5,Написати тести,LOW,DONE
```

Порядок колонок визначається назвами Java-полів:

1. `assignee`
2. `estimatedHours`
3. `name`
4. `priority`
5. `status`

Якщо значення містить кому, подвійну лапку або перенесення рядка, воно записується з урахуванням правил CSV-екранування. Подвійна лапка всередині такого значення подвоюється.

**Сумісність:** новий CSV-формат лабораторної №5 не замінює старий формат із крапкою з комою, який використовує попередня функціональність. Старий формат та його парсер збережено.

## Обробка помилок

Для помилок CSV передбачено власний виняток `CsvFormatException`.

Він підтримує конструктори для повідомлення про помилку та повідомлення разом із початковою причиною:

```java
CsvFormatException(String message)

CsvFormatException(String message, Throwable cause)
```

Збереження початкової причини допомагає визначити джерело помилки, наприклад некоректне числове значення або помилку введення-виведення.

Обробляються такі випадки:

- неправильна кількість полів;
- некоректне числове значення;
- невідоме значення enum;
- незакриті подвійні лапки;
- помилки читання або запису файлів;
- некоректна структура CSV.

Помилки не повинні мовчки поглинатися порожнім блоком `catch`, оскільки це приховує проблеми та ускладнює діагностику.

## Рівність об'єктів

У класі `ProjectTaskRecord` реалізовано `equals()` та `hashCode()`.

Логічна ідентичність задачі визначається комбінацією двох полів:

- `name` — назва задачі;
- `assignee` — виконавець.

Для перевірки логічної ідентичності передбачено метод:

```java
hasSameIdentity(ProjectTaskRecord other)
```

Логічна ідентичність і повна рівність об'єктів мають різне призначення. Метод `hasSameIdentity()` перевіряє збіг назви задачі та виконавця, тоді як `equals()` і `hashCode()` враховують усі поля запису.

Автоматичні тести перевіряють рівність об'єктів і узгодженість `equals()` та `hashCode()`.

## Тестування

Тести лабораторної №5 зосереджені в `CsvRepositoryTest`.

Перевіряються:

- додавання елементів у `Repository<T>`;
- пошук через `Predicate`;
- отримання знімка репозиторію;
- експорт та імпорт CSV;
- збереження ком, лапок і перенесень рядків;
- детермінований порядок заголовків;
- порожній файл і порожній набір даних;
- неправильна кількість полів;
- некоректне числове значення;
- невідоме значення enum;
- незакриті лапки;
- обробка файлових помилок;
- збереження початкової причини винятку;
- `equals()` та `hashCode()`;
- логічна ідентичність записів.

Round-trip тест перевіряє експорт та повторний імпорт п'яти записів, серед яких є значення з комою, подвійними лапками та перенесенням рядка.
