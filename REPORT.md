## 3. Постановка задачі

### Формат запису

Для варіанта 22 використовується формат:

```text
title;assignee;estimateHours;priority;done
```

Поля:

- `title` — назва задачі;
- `assignee` — виконавець;
- `estimateHours` — оцінка задачі в годинах;
- `priority` — числовий пріоритет;
- `done` — ознака виконання задачі.

Дані читаються з текстового CSV-файлу у кодуванні UTF-8.

### Валідація

Програма перевіряє:

- порожні рядки;
- кількість полів;
- порожню назву задачі;
- порожнє поле виконавця;
- числовий формат `estimateHours`;
- числовий формат `priority`;
- невід'ємність `estimateHours`;
- значення поля `done`, яке має бути `true` або `false`.

Невалідні записи не потрапляють до розрахунку метрик. Для помилкового рядка виводиться його номер та причина помилки.

### Чотири показники варіанта 22

Програма обчислює:

1. кількість валідних задач;
2. сумарну оцінку годин;
3. середній пріоритет;
4. кількість виконаних задач.

## 4. Структура програми

Основні класи програми:

### `Main`

Є точкою входу в програму.

Виконує:

- обробку параметрів командного рядка;
- створення `TaskParser`;
- створення `TaskMetrics`;
- створення `ReportFormatter`;
- запуск читання даних;
- обчислення метрик;
- виведення звіту;
- запис звіту у файл.

Підтримуються параметри:

```text
--help
--version
--input FILE
--output FILE
```

### `Task`

Модель одного запису про проєктну задачу.

Містить:

```text
title
assignee
estimateHours
priority
done
```

### `TaskParser`

Відповідає за:

- читання файлу;
- розбиття рядка на поля;
- валідацію;
- перетворення числових значень;
- створення об'єктів `Task`.

Невалідні записи відкидаються та супроводжуються повідомленням про помилку.

Якщо після обробки не залишилось жодного валідного запису, генерується `IllegalArgumentException`.

### `TaskMetrics`

Окремо реалізує обчислення метрик:

- `totalEstimateHours`;
- `averagePriority`;
- `countCompletedTasks`.

### `ReportFormatter`

Формує єдиний текстовий звіт на основі вже обчислених значень.

Для форматування використовується `Locale.ROOT`, а числові значення мають два знаки після крапки.

### Потік даних

```text
data/input.csv
       ↓
  TaskParser
       ↓
    List<Task>
       ↓
   TaskMetrics
       ↓
  готові метрики
       ↓
 ReportFormatter
       ↓
 String report
   ↙         ↘
консоль     файл
```

## 5. Інфраструктура

### Maven

Проєкт описано у `pom.xml`.

Використовується:

```text
Java 21
UTF-8
Maven Wrapper
```

Основні залежності та плагіни:

- JUnit Jupiter 5.12.2;
- Maven Compiler Plugin 3.13.0;
- SpotBugs Maven Plugin 4.9.7.0;
- Maven Shade Plugin 3.6.0.

### Maven Wrapper

На macOS/Linux використовується:

```bash
./mvnw
```

На Windows:

```cmd
mvnw.cmd
```

Це дозволяє запускати Maven-збірку без вимоги встановлювати конкретну версію Maven глобально.

### JUnit

JUnit використовується як тестова залежність:

```text
org.junit.jupiter:junit-jupiter:5.12.2
```

### SpotBugs

SpotBugs прив'язаний до фази:

```text
verify
```

Під час локальної перевірки:

```bash
./mvnw -B verify
```

отримано:

```text
BugInstance size is 0
Error size is 0
No errors/warnings found
BUILD SUCCESS
```

### Executable JAR

Для пакування використовується Maven Shade Plugin.

Збірка:

```bash
./mvnw -B clean package
```

Фактичний JAR:

```text
target/maven-actions-hello-0.1.0.jar
```

Перевірено запуск:

```bash
java -jar target/maven-actions-hello-0.1.0.jar --version
```

Результат:

```text
0.1.0
```

## 11. Відповіді на контрольні питання

### 1. Яке призначення файла `pom.xml`?

`pom.xml` описує Maven-проєкт: його координати, версію Java, залежності та плагіни. Через нього Maven знає, як компілювати, тестувати, аналізувати й пакувати проєкт.

### 2. Чим відрізняються фази `test`, `verify` і `package`?

`test` компілює тестовий код і запускає тести.

`verify` проходить попередні фази та виконує додаткові перевірки, зокрема SpotBugs у цьому проєкті.

`package` проходить попередні фази та створює JAR.

### 3. Навіщо потрібен Maven Wrapper?

Maven Wrapper дає змогу запускати Maven-команди через `./mvnw` або `mvnw.cmd`, не вимагаючи однакової глобальної установки Maven на кожному комп'ютері.

### 4. Яку роль відіграє метод `main`?

Метод `main` є точкою входу Java-програми. Саме з нього починається виконання.

### 5. Чим примітивний тип відрізняється від `String`?

Примітивні типи, такі як `int`, `double` і `boolean`, безпосередньо представляють прості значення.

`String` є об'єктним посилальним типом і використовується для роботи з текстом.

### 6. Чому середнє потрібно обчислювати в `double`, навіть якщо сума й кількість мають тип `int`?

Тому що результат ділення може бути дробовим. Якщо використовувати лише цілочисельне ділення, дробова частина буде втрачена.

### 7. Що станеться, якщо `Integer.parseInt` отримати рядок `"abc"`?

Метод не зможе перетворити текст на число та викине `NumberFormatException`.

### 8. Чому не можна мовчки пропускати рядок із помилкою?

Користувач має розуміти, чому дані не потрапили до розрахунків. Тому програма виводить номер рядка та причину помилки.

### 9. Як `String.split(";", -1)` обробляє порожнє останнє поле?

Параметр `-1` змушує `split` зберігати порожній останній елемент. Це важливо для перевірки кількості полів і виявлення порожніх значень.

### 10. Чому для шляхів краще використовувати `Path.of`, а не `"data\\input.csv"`?

`Path.of` використовує абстракцію шляхів Java і краще переноситься між Windows, macOS та Unix-подібними системами.

### 11. Навіщо явно задавати `StandardCharsets.UTF_8`?

Щоб однаково інтерпретувати українські та інші символи незалежно від системних налаштувань кодування.

### 12. Чим `%n` відрізняється від `\n` у форматованому виводі?

`%n` у `String.format` вставляє платформозалежний правильний символ нового рядка. Це зручніше для кросплатформного форматованого виводу.

### 13. Які дані потрібно перевірити у вашому варіанті?

Потрібно перевірити кількість полів, текстові поля `title` та `assignee`, числові поля `estimateHours` і `priority`, невід'ємність `estimateHours` та коректність `done`.

### 14. Які тести виявлять помилку в обчисленні середнього?

Потрібен тест із кількома задачами, для яких відоме точне середнє значення. Наприклад, для пріоритетів `1`, `2`, `3` очікуване середнє дорівнює `2.0`.

### 15. Яке призначення статичного аналізатора?

Статичний аналізатор шукає потенційні проблеми в коді або байт-коді без виконання програми як звичайного сценарію. У цьому проєкті SpotBugs запускається під час `verify`.

### 16. Яку роль виконує GitHub Actions?

GitHub Actions автоматизує збірку та перевірки. У цьому проєкті CI запускає Maven на Ubuntu, Windows і macOS та публікує JAR як artifact.

### 17. Що має містити GitHub Issue на дефект?

Issue має описувати проблему так, щоб її можна було відтворити: кроки відтворення, очікуваний результат і фактичний результат.

### 18. Що потрібно вказати у розділі звіту про академічну доброчесність?

Потрібно вказати інструменти ШІ, ролі, запити, прийняті рекомендації, виправлені помилки та підтвердити, що автор розуміє поданий код.

### 19. Яку роботу виконує агент DevOps, а яку — агент Валідатор?

DevOps допомагає з Maven, аналізаторами, пакуванням і GitHub Actions.

Валідатор допомагає скласти крайові випадки, перевірити результати та виявляти дефекти.

### 20. Який рядок програми найскладніше пояснити і чому?

Найбільш нетривіальним є форматування через `String.format` із `Locale.ROOT` та `%n`, тому що тут одночасно враховується формат чисел, локаль і кросплатформний перенос рядка.
