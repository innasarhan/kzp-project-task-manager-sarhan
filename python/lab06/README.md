# Обробка даних проєктних задач засобами Python

## Опис проєкту

У межах цієї роботи я розробила Python-пакет для обробки даних проєктних задач із CSV-файлу. Програма зчитує дані, перевіряє їхню коректність, виконує аналіз і формує текстовий звіт.

Мій варіант завдання — № 22. Предметна область — проєктні задачі.

## Структура проєкту

Під час розробки я розподілила програму на окремі модулі:

- `loader.py` — зчитування CSV-файлу, перевірка даних і перетворення кількості годин на ціле число.
- `analysis.py` — фільтрація задач, обчислення загальної кількості годин і групування даних за відповідальними особами.
- `reporting.py` — формування текстового звіту.
- `cli.py` — запуск програми через командний рядок.
- `errors.py` — визначення власного винятку для помилок даних.

Також я створила каталог `tests/` з автоматизованими тестами, каталог `data/` із вхідними даними та каталог `reports/` для сформованого звіту.

## Вхідні дані

Я підготувала CSV-файл `data/tasks.csv` із такими полями:

| Поле | Призначення |
|---|---|
| `name` | Назва задачі |
| `assignee` | Відповідальна особа |
| `hours` | Кількість годин |
| `status` | Статус задачі |
| `priority` | Пріоритет задачі |

Під час зчитування даних я використала `csv.DictReader`, кодування UTF-8 і параметр `newline=""`. Текстові значення очищуються від зайвих пробілів, а статус і пріоритет переводяться в нижній регістр. Значення `hours` перетворюється на ціле число.

## Аналіз даних

У програмі я реалізувала такі операції:

- відбір задач, статус яких не дорівнює `done`;
- підрахунок кількості активних задач;
- обчислення загальної кількості годин;
- групування годин за відповідальними особами;
- визначення унікальних відповідальних осіб;
- відбір задач із високим пріоритетом.

Для обробки даних я використала списки, словники, множини та включення списків (list comprehensions).

## Формування звіту

Я реалізувала формування текстового звіту у файлі `reports/report.txt`. Звіт містить кількість активних задач, загальну кількість годин, розподіл годин за відповідальними особами, список унікальних виконавців і перелік задач із високим пріоритетом.

Для запису результатів я використала `pathlib.Path`, контекстний менеджер `with` і кодування UTF-8.

## Обробка помилок

Я додала перевірки вхідних даних. Програма повідомляє про відсутні обов’язкові стовпці, пропущені значення, некоректну кількість годин, від’ємні значення та помилки читання файлу.

Для помилок даних я створила власний клас `DataError`. У повідомленнях про некоректну кількість годин зазначаються номер рядка, назва поля та неправильне значення. У разі помилки CLI повертає ненульовий код завершення.

## Запуск програми

Я налаштувала запуск програми через командний рядок із зазначенням вхідного CSV-файлу та шляху до вихідного звіту:

```bash
python -m project_tasks.cli data/tasks.csv reports/report.txt
```

Також у `pyproject.toml` я налаштувала команду `project-tasks` для запуску встановленого пакета.

## Тестування та перевірка якості коду

Я створила автоматизовані тести для перевірки завантаження даних, аналізу, формування звіту та роботи CLI.

Під час локальної перевірки я виконала команду:

```bash
pytest
```

Результат останнього запуску: **17 passed**.

Також я перевірила якість коду за допомогою Ruff і виправила форматування файлів. Перевірка форматування завершилася успішно: `12 files already formatted`.

## Збирання пакета

Я налаштувала параметри пакета у файлі `pyproject.toml` і вказала версію `6.0.0`.

Для збирання пакета я використала:

```bash
python -m build
```

Збирання завершилося успішно. Було створено два дистрибутиви:

- `project_tasks-6.0.0.tar.gz`
- `project_tasks-6.0.0-py3-none-any.whl`

Я також встановила wheel у окреме віртуальне середовище та перевірила запуск CLI. Програма сформувала звіт із 6 активними задачами та загальною кількістю 26 годин.

## Автоматизація перевірок

Я створила конфігурацію GitHub Actions у файлі `.github/workflows/python-ci.yml`. У ній налаштовано запуск тестів, перевірки Ruff, перевірки форматування та збирання пакета для Ubuntu, macOS і Windows із Python 3.11, 3.12 і 3.13.

Віддалений запуск CI на GitHub ще потрібно перевірити після завантаження проєкту до репозиторію.
