# Об'єктно-орієнтована обробка даних проєктних задач засобами Python

## Опис проєкту

У межах цієї роботи я модернізувала Python-пакет для обробки даних проєктних задач із CSV-файлу, перетворивши словникові записи на об'єкти з власною поведінкою. Програма зчитує дані, перевіряє їхню коректність, виконує аналіз і формує текстовий звіт.

Мій варіант завдання — № 22. Предметна область — проєктні задачі.

Основна мета роботи — застосувати об'єктно-орієнтоване програмування в Python, використати властивості, наслідування, поліморфізм, спеціальні методи, протокол `Protocol` та незмінний клас даних `dataclass`.

**Версія проєкту:** `7.0.0`.

## Структура проєкту

Під час розробки я розподілила програму на окремі модулі:

- `models.py` — базовий клас `ProjectTask`, підкласи `DevelopmentTask` і `TestingTask`, протокол `ScoredTask` та незмінний клас `AssigneeWorkload`.
- `loader.py` — зчитування CSV-файлу, перевірка даних і створення об'єктів задач.
- `analysis.py` — фільтрація задач, обчислення кількості годин, групування даних за виконавцями та розрахунок оцінок пріоритету.
- `reporting.py` — формування текстового звіту.
- `cli.py` — запуск програми через командний рядок.
- `errors.py` — визначення власного винятку `DataError`.

Також я створила каталог `tests/` з автоматизованими тестами, каталог `data/` із вхідними даними та каталог `reports/` для сформованого звіту.

У каталозі `.github/workflows/` розміщено конфігурацію `ci.yml` для автоматизації перевірок проєкту через GitHub Actions.

## Об'єктна модель

У цій лабораторній роботі я реалізувала базовий клас `ProjectTask`, який представляє проєктну задачу. Він зберігає назву задачі, виконавця, кількість годин, статус і пріоритет.

Для контрольованого доступу до даних використано `@property` і setter-методи. Вони перевіряють значення та не дозволяють встановлювати некоректні дані.

На основі базового класу створено два підкласи:

- `DevelopmentTask` — для задач розроблення.
- `TestingTask` — для задач тестування.

Обидва підкласи реалізують метод `priority_score()`, але обчислюють оцінку пріоритету за різними правилами. Це демонструє використання наслідування та поліморфізму.

Також я реалізувала протокол `ScoredTask`, який визначає спільний інтерфейс для об'єктів, що мають необхідні атрибути та метод `priority_score()`.

Для збереження підсумкових даних про навантаження виконавців використано `AssigneeWorkload`, створений за допомогою `@dataclass(frozen=True)`. Такий об'єкт не дозволяє змінювати свої поля після створення звичайним присвоєнням.

У класі `ProjectTask` також реалізовано спеціальні методи `__str__()`, `__repr__()` і `__eq__()`, а для визначення порядку сортування задач використано метод `sort_key()`.

## Вхідні дані

Я використала CSV-файл `data/tasks.csv` із такими полями:

| Поле | Призначення |
|---|---|
| `name` | Назва задачі |
| `assignee` | Відповідальна особа |
| `hours` | Кількість годин |
| `status` | Статус задачі |
| `priority` | Пріоритет задачі |

Під час зчитування даних використовується `csv.DictReader`, кодування UTF-8 і параметр `newline=""`.

Програма перевіряє наявність обов'язкових стовпців, заповнення полів, коректність кількості годин, допустимість статусу та пріоритету.

Після перевірки кожен CSV-запис перетворюється на об'єкт `DevelopmentTask` або `TestingTask`. Якщо назва задачі містить слово `test` без урахування регістру, створюється об'єкт `TestingTask`; в інших випадках — `DevelopmentTask`.

## Аналіз даних

У програмі я реалізувала такі операції:

- відбір активних задач, статус яких не дорівнює `done`;
- підрахунок кількості активних задач;
- обчислення загальної кількості годин;
- групування годин за відповідальними особами;
- визначення унікальних виконавців;
- відбір задач із високим пріоритетом;
- обчислення оцінки пріоритету для різних типів задач;
- формування підсумкових об'єктів навантаження виконавців.

Функція аналізу підтримує додаткові параметри фільтрації, зокрема мінімальну кількість годин, можливість врахування виконаних задач і фільтрацію за статусами.

Для взаємодії з різними типами задач використовується протокол `ScoredTask`. Завдяки цьому модуль аналізу працює зі спільним інтерфейсом, а не залежить від перевірок кожного конкретного підкласу.

## Формування звіту

Я реалізувала формування текстового звіту у файлі `reports/report.txt`.

Звіт містить кількість активних задач, загальну кількість годин, розподіл годин за виконавцями, список унікальних виконавців і перелік задач із високим пріоритетом.

Для запису результатів використовується `pathlib.Path`, контекстний менеджер `with` і кодування UTF-8. Програма створює необхідні батьківські каталоги для вихідного файлу.

Також я перевірила збереження контрольних результатів попередньої роботи. Для наявного набору даних очікуються 6 активних задач і 26 годин загалом, зокрема 9 годин для Anna, 4 години для Ivan і 13 годин для Oleh.

## Обробка помилок

Я реалізувала перевірки вхідних даних і обробку помилок читання та запису файлів.

Програма обробляє такі ситуації:

- відсутній вхідний файл;
- порожній CSV-файл або відсутній заголовок;
- відсутні обов'язкові стовпці;
- пропущені або порожні значення;
- некоректна кількість годин;
- від'ємні значення годин;
- недопустимі статуси та пріоритети;
- некоректна структура CSV-записів.

Для помилок даних я створила власний клас `DataError`. У повідомленнях про некоректні дані зазначається відповідна інформація, зокрема номер рядка або назва поля, якщо це можливо визначити.

У CLI реалізовано обробку помилок читання та запису. У разі помилки програма повертає ненульовий код завершення, а в разі успішного виконання — код `0`.

## Запуск програми

Я налаштувала запуск програми через командний рядок із зазначенням вхідного CSV-файлу та шляху до вихідного звіту.

Після активації віртуального середовища та встановлення пакета програму можна запустити командою:

```bash
project-tasks data/tasks.csv reports/report.txt
```

Також можна виконати програму як Python-модуль:

```bash
python -m project_tasks.cli data/tasks.csv reports/report.txt
```

У файлі `pyproject.toml` налаштовано команду `project-tasks` для запуску встановленого пакета.

## Тестування та перевірка якості коду

Я створила автоматизовані тести для перевірки об'єктної моделі, завантаження даних, аналізу, формування звіту та роботи CLI.

Для запуску тестів я використала команду:

```bash
python -m pytest
```

Останній підтверджений результат локальної перевірки:

**39 passed in 0.19s**

Тестами перевіряються створення об'єктів, властивості та їх валідація, незмінність `AssigneeWorkload`, робота спеціальних методів, сортування, поведінка підкласів, відповідність протоколу, обробка некоректних CSV-записів, результати аналізу, формування звіту та коди завершення CLI.

Для перевірки якості коду я використала Ruff.

Перевірка стилю та типових помилок виконується командою:

```bash
python -m ruff check .
```

Результат останньої перевірки:

```text
All checks passed!
```

Перевірка форматування виконується командою:

```bash
python -m ruff format --check .
```

Останній підтверджений результат:

```text
14 files already formatted
```
